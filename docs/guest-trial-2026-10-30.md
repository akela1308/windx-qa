# Пробный сайт до регистрации

30 октября 2026. Прямое решение владельца: посетитель сразу создаёт пробный сайт и может опубликовать его. Для дальнейших правок и управления нужен аккаунт; пробный сайт должен переходить в этот аккаунт.

## Сценарий

1. Главная, шаблоны и стили открываются без входа. На главной сразу доступен запрос создания сайта.
2. Только при создании появляется гостевая личность со случайным идентификатором и секретной cookie. Пустой визит cookie сессии не создаёт.
3. Гость видит свой результат и может подтвердить сведения для первой публикации. Существующая проверка выдуманных фактов сохранена: без подтверждения контактов, цен и других сведений публикация блокируется. Если данные неверны, исправление требует аккаунта, как и другие правки.
4. Первая публикация доступна без регистрации. После неё предлагаются регистрация или вход. AI-правки, свой код, история с возвратом версий, переименование, копирование, избранное, удаление и снятие с публикации требуют зарегистрированной личности. Ограничение проверяется на сервере до обращения к AI.
5. При регистрации или входе гостевой сайт привязывается к подтверждённой сессией личности этого браузера. Сохраняются ID сайта, адрес, опубликованная версия, факты и история. Парольный вход возвращает прямо к тому же сайту; старый гостевой токен отзывается. Это не присвоение всех старых сайтов по email или IP.

## Изоляция и привязка

IP не служит доказательством владения. Два человека в одной сети получают независимые секретные сессии и не видят чужие черновики. По одному URL редактора сайт другому браузеру не открывается. Опубликованная страница, как и раньше, общедоступна.

`getStore()` допускает посетителя без личности, гостя и зарегистрированного владельца. Посетителю возвращается пустое хранилище, а не общий список. `getManageStore()` требует зарегистрированную сессию. `OwnedSiteStore` дополнительно ограничивает гостевые записи на уровне данных: только первый документ, подтверждение фактов до публикации и первая публикация. Нет гостевой перезаписи версии, предложения правок или снятия с публикации.

Привязка при входе одноразовая, с серверной записью получателя. Второй одновременный вход в другой аккаунт не переприсваивает уже сохранённый сайт. Другие гостевые, старые бесхозные и чужие зарегистрированные сайты не затрагиваются. Для пяти прежних сайтов владельца остаётся уже настроенное персональное приглашение. Plainsheet Studio не изменяется.

## Временные ограничения пробного режима

Гипотеза до утверждения тарифов: один созданный пробный сайт на гостевую сессию, три попытки на IP и двадцать гостевых генераций суммарно за сутки UTC. Настройки: `WINDX_TRIAL_DAILY_PER_IP` и `WINDX_TRIAL_DAILY_TOTAL`. Это защита текущего бюджета, не утверждённый тариф и не полная защита от злоупотреблений зарегистрированными аккаунтами.

Счётчики файловые и сохраняются после перезапуска. Одновременные попытки резервируют слот атомарно. Неудачная генерация освобождает резерв браузера для повторного запроса, но попытка в суточном бюджете остаётся учтённой: запрос к AI мог уже стоить денег. Заблокированный по IP запрос не расходует глобальный слот. До проверки лимита новая сессия не записывается, чтобы отклонённые запросы не накапливали файлы сессий.

На Railway используется X-Real-IP, описанный в [официальной спецификации public networking](https://docs.railway.com/networking/public-networking/specs-and-limits). IP сохраняется только в виде HMAC с закрытым серверным ключом, не используется в адресах сайта или правах доступа. При отсутствии корректного IP применяется общий ограничительный ключ. Общий суточный лимит не зависит от возможности сменить IP. На другом хостинге нужно отдельно проверить границу доверия заголовкам прокси.

Гостевой доступ действует до 30 дней в исходном браузере; удаление cookie прекращает доступ раньше. Опубликованный сайт автоматически не удаляется и не снимается с публикации при истечении гостевого доступа. Срок бесплатного размещения опубликованного пробного сайта требует отдельного решения; здесь не добавлялось автоматическое удаление или обещание определённого тарифа.

## Проверка

```sh
node --import tsx tests/guest-trial.mts
node --import tsx tests/auth-isolation.mts
node --import tsx tests/google-auth.mts
npm run build
node --import tsx tests/auth-http.mts
npx tsc --noEmit
git diff --check
```

Сквозной HTTP-тест поднимает локальную production-сборку с одноразовым каталогом и демо-провайдером. Проверяет реальную отправку форм создания и регистрации, гостевую cookie, блокировку публикации до подтверждения фактов, первую публикацию, запрет правок, переход сайта в аккаунт без смены адреса, отзыв старой cookie и разрешение правки после регистрации. Дополнительно сохраняются проверки чужих аккаунтов, закрытых предпросмотров и публикации только выбранной версии.

В браузере отдельно пройден путь на localhost: создание без входа, подтверждение сведений, публикация, регистрация одноразового тестового аккаунта и открытие полного редактора того же сайта. Платные AI-вызовы и внешние тестовые публикации не выполнялись. Для локальной ссылки публикации исправлен порт: берётся фактический PORT Next.js, а не всегда 3000.

Настройка Google остаётся приостановленной по просьбе владельца. Подготовленный Google-код не включается. Центральная привязка гостевого сайта находится в `signIn`, поэтому не зависит от способа входа.

По отдельной просьбе владельца 30 октября решение внесено в мастер-контекст: создание и первая публикация доступны до регистрации, дальнейшие правки и управление требуют аккаунта. Прежний порядок с обязательной регистрацией до первого результата заменён.
