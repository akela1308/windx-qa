# Этап B: проверка живой публикации, 29.10.2026

Проверка по `docs/audit-2026-10-29.md`. Цикл публикации пройден, найдены проблемы. Код приложения в этом этапе не менялся. Этап C не начат.

## Объект и границы проверки

В рабочем кабинете создана копия примера Lowgear Cycle Works, исходные четыре сайта не изменены. Тестовая копия: `4f9e5ea7`, название в кабинете `WINDX Publication Test 20261029`.

Адрес: https://windx-publication-test-20261029.windx.app/

Страница помечена заголовком `DEMO ONLY`. Контакты для теста: `+44 20 7946 0958` и `publication-test@example.com`. Статусы фактов подтверждались только в тестовой копии для проверки механизма публикации; это не подтверждение существования бизнеса, его адреса, цен или часов работы. Реальные звонки и отправка писем не выполнялись.

Проверены Chrome, отдельный Safari на компьютере и настоящий телефон владельца. Дополнительно проверен Chrome с шириной 390 пикселей. Модель телефона, версия ОС и браузер на телефоне отдельно не устанавливались.

## Найденные проблемы

1. **AI-правка убрала возможность позвонить.** В исходной копии была кнопка `tel:02079460123`. Просьба заменить номер и добавить email привела к замене единственной кнопки блока на `mailto:`. AI прямо объяснил это ограничением выбранной композиции. Вместо сохранения обеих возможностей номер стал обычным текстом. Нужно сохранять ссылки телефона и почты независимо от числа основных кнопок.

2. **Узкая правка изменила другие части сайта.** Просьба поменять только заголовок, оставив всё остальное неизменным, также переместила FAQ и добавила два блока: крупную цену и рисунок. AI написал об этом в ответе. Вторая правка заголовка, уже после публикации, такого видимого расширения не заявила. Нужна проверка границ правки: общие проверки дизайна не должны вынуждать менять несвязанные разделы.

3. **На телефоне сохранилось состояние отсутствующего сайта после повторной публикации.** Владелец дважды увидел `No site at this address yet.`, хотя после повторной публикации свежий запрос с компьютера уже возвращал 200. Новая вкладка с `?check=20261029B` открылась. Это согласуется с кешированием прежнего 404, но точный слой кеша не установлен. Шесть диагностических запросов, включая мобильный User-Agent, вернули 200. У опубликованной страницы заголовок `Cache-Control: public, max-age=60`, у 404 явного `Cache-Control` нет. Нужно определить и проверить политику кеширования обоих ответов при публикации и снятии с публикации. Уже открытая страница также сама не исчезает после снятия публикации.

4. **Один запрос к AI завершился ошибкой всего редактора.** Первая составная просьба обозначить демо и очистить контакты завершилась экраном `This page couldn’t load`; в консоли: `An unexpected response was received from the server.`. После Reload редактор открыл версию 1, результат не сохранился. Более короткие следующие запросы создали версии 2, 3 и 4. Причина серверной ошибки не установлена. Подключённый Railway-аккаунт не показывает проект windx, а локальный CLI не связан с ним, поэтому логи именно этого сервиса не были доступны. Новый аккаунт, сервис или подключение не создавались.

В папке [stage-b-2026-10-29](stage-b-2026-10-29/) сохранены скриншоты публикации, мобильной ширины, Safari, разделения версий, снятия публикации и настоящий скриншот телефона владельца. Файлы `http-evidence.json`, `phone-access-diagnostics.json` и `editor-console-errors.json` содержат наблюдения. Времена в JSON записаны в UTC.

Команда для просмотра текущего HTTP-ответа:

```bash
curl -i 'https://windx-publication-test-20261029.windx.app/?check=manual'
```

Сейчас ожидаются 200 и `DEMO ONLY: published update test B`. Для повторения полного цикла открыть https://www.windx.app/sites/4f9e5ea7, нажать `Live`, затем `Take offline`: свежий запрос должен вернуть 404. Нажать `Publish now`: свежий запрос должен снова вернуть 200. Проверять также ранее открытую вкладку, чтобы воспроизвести сохранённый ответ.

Общий итог: публикация, отделение черновика от живой версии, обновление и снятие публикации работают в проверенном сценарии. Телефонная ссылка после AI-правки сломана, границы правки и поведение кеша требуют исправлений. Этот отчёт не означает, что все сценарии публикации или работа с реальными заявками проверены.
