# Восстановление ручного текста, 4 ноября 2026

## Результат

Во вкладке «Текст и изображения» добавлено восстановление неприменённого текстового ввода. Раньше после ухода или обновления страницы оставалось только предупреждение о потере правки. Теперь изменения текста и ссылок записываются локально при вводе; последующее открытие предлагает восстановить нужный раздел.

## Поведение

- Отдельная запись для аккаунта, сайта и раздела. Можно оставить несколько текстовых правок в разных разделах, включая название и описание страницы. В копии только изменённые текстовые поля, а не весь документ.
- При переходе между разделами уже сохранённый текст остаётся доступным для восстановления. Если запись не удалась, есть изменения фотографий или отмеченные подтверждения фактов, предупреждение об уходе сохраняется.
- Восстановление требует явного нажатия. Оно выбирает исходный раздел и возвращает текст только в его известные поля. Не создаёт версию, не меняет публикацию и не запускает AI.
- Для другой версии, удалённого раздела, другой композиции или изменившихся полей автоматическое восстановление недоступно. Сохраняются просмотр и копирование текста. Затем можно удалить локальную копию и вручную перенести текст в актуальный раздел.
- Восстановленный ввод проходит обычную серверную проверку, просмотр изменений и применение. Публикация остаётся отдельным действием. Пустые поля и неверные ссылки можно восстановить как ввод, но нельзя применить в обход прежней валидации.
- Успешная подготовка собственного серверного предложения очищает локальную копию только затронутого раздела. Остальные копии остаются. Чужое ожидающее предложение не должно удалять текстовые черновики.
- Сброс правки удаляет копию текущего раздела. Выход через меню аккаунта очищает локальные копии текста и кода WINDX, не затрагивая настройки и другие данные браузера.
- Повреждённые, слишком большие, будущие и просроченные записи отклоняются. При запрете или переполнении localStorage пользователь видит предупреждение. Функция не мешает обычному ручному редактированию без локальной копии.
- Тексты интерфейса доступны на EN/RU/ES. Сохранённые строки выводятся как экранированный текст, не HTML.

## Границы

Копии доступны для восстановления 7 дней в этом браузере. Истёкшие записи удаляются при следующем чтении. Это не межкомпьютерная синхронизация, не версия сайта и не резерв платформы. Вкладки, одновременно меняющие один раздел, не объединяются: последняя запись заменяет предыдущую.

Изображения, их кадрирование/описания внутри объекта фотографии, незавершённое добавление новой картинки и галочки подтверждения фактов не восстанавливаются. После восстановления берутся фотографии сохранённой версии, отметки фактов сбрасываются. Подпись уже существующей картинки как отдельное обычное текстовое поле восстанавливается. Восстановление всего свободного холста и AI-запроса не входит в этот этап.

localStorage не является сейфом для секретов. Ни пароли, ни ключи, ни заявки посетителей этот механизм не читает. Вызовы AI, письма, подписки и внешние сервисы не добавлялись.

## Проверки

Пройдены локально:

```sh
npm run build:webpack
node --import tsx tests/text-drafts.mts
node --import tsx tests/code-drafts.mts
node --import tsx tests/content.mts
node --import tsx tests/content-http.mts
node --import tsx tests/journey-http.mts
npx tsc --noEmit
git diff --check
```

ESLint затронутых файлов также пройден. HTTP-тесты используют временные данные, локальные письма и AI_DEMO. Проверены прежняя изоляция владельцев, загрузки, защита Origin, ограничения путей/ссылок, просмотр/отмена/применение, раздельные черновик и публикация, история, формы, три отчёта и аккаунт.

Новый тест проверяет пространства аккаунтов/сайтов/разделов, сохранность нескольких копий и metadata, исключение фотографий и подтверждений, пустой ввод, границы полей/типов/версий, повреждённые и истёкшие записи, ошибку квоты, безопасное отображение на трёх языках и адресную очистку localStorage.

В браузере на локальной production-сборке:

1. Обычный вход в синтетический тестовый аккаунт.
2. Изменение title/description и переход к первому экрану: прежний текст сохранился.
3. Изменение headline, открытие сайта в другой вкладке: найдены обе независимые копии.
4. Явное восстановление точного headline в правильный раздел.
5. Очистка обязательного headline, обычная серверная ошибка «Fill in “Headline”. Your input is kept.». Пустой ввод сохранился и был повторно восстановлен.
6. Корректный headline прошёл просмотр и применение в локальную версию 2. Копия metadata осталась, но уже с отметкой другой версии и без кнопки автоматического восстановления.
7. Выход и повторный вход удалили локальные текстовые копии. Версия 2 осталась сохранена.

Локальный сервер остановлен, временные данные и HTML-стенд удалены. Снимок: `data/verification/text-drafts-2026-11-04/local-stale.png`, вне git. В управлении native confirm встроенного браузера была задержка; это не выдано за дефект продукта. Обычный переход между разделами после успешной записи текста проверен в финальной сборке.

## Ручная проверка

В своём демо-сайте откройте «Текст и изображения», измените текст без применения. Перейдите к другому разделу и измените его текст. Откройте этот же сайт заново: появятся отдельные предложения восстановления. Нажмите «Восстановить текст». Для изменения сайта затем нужны просмотр и применение; для посетителей ещё нужна публикация.
