# Подтверждение почты: другой аккаунт в браузере

3 ноября 2026 года, живой проход нового клиента.

## Что произошло

Новый тестовый аккаунт зарегистрирован во встроенном браузере. Письмо открыто в Gmail через Chrome, где уже был выполнен вход в другой аккаунт WINDX. Проверка принадлежности ссылки правильно запретила подтверждение чужой почты, но интерфейс неверно объяснил отказ: «Ссылка неверна, истекла или уже использована».

Письмо было свежим. Та же исходная ссылка открыта из настоящего письма в браузере с нужным аккаунтом; адрес успешно подтверждён. Повторного письма и ручного изменения статуса на сервере не потребовалось.

## Исправление

- Живая ссылка для другого аккаунта возвращает отдельное состояние `wrongAccount`, без раскрытия почты получателя и без расходования ссылки.
- Интерфейс объясняет различие аккаунтов и предлагает открыть ссылку в браузере регистрации либо выйти и сменить аккаунт.
- Кнопка смены аккаунта завершает текущую сессию и предлагает вход в отдельной вкладке. Форма сохраняет ссылку в памяти, чтобы после входа можно было вернуться и подтвердить адрес.
- Неверные, использованные и просроченные ссылки по-прежнему отклоняются. Автоматического подтверждения при GET нет.
- Убрано лишнее обновление серверного дерева после подтверждения: оно могло возвращать fragment в адресную строку после его очистки. Статус аккаунта перечитывается при переходе в аккаунт.
- Сообщения добавлены на русском, английском и испанском.

## Проверка

```sh
node --import tsx tests/account-security.mts
npx next build --webpack
node --import tsx tests/verification-account-http.mts
```

Пройдены модульные проверки одноразовых ссылок и production HTTP-проверка действий: чужой аккаунт → понятный отказ → ссылка остаётся рабочей → её владелец подтверждает почту → повторное использование запрещено. Отдельно проверено, что смена аккаунта отзывает только текущую сессию. Данные тестов изолированы, настоящие письма этими тестами не отправляются.

Живое доказательство исходной причины и успешного подтверждения: `data/verification/live-journey-2026-11-03/email-confirmed.png` (локальный файл, не включается в git).

Полный путь создания нового сайта, правок, публикации и заявки продолжается отдельно; подтверждение почты само по себе не означает завершение этого пути.
