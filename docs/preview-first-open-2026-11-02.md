# Первое открытие превью редактора — 2 ноября 2026

## Что найдено

Пустота возникала при первоначальной навигации iframe, а не из-за отсутствующей версии сайта: защищённый адрес той же версии возвращал HTML, открытие отдельно и ручное обновление работали.

Редактор выводится через streaming SSR внутри Suspense. Раньше серверная разметка сразу содержала iframe с адресом страницы. React переносит готовую часть Suspense из временного контейнера через удаление и повторную вставку узлов. Это прерывает начавшуюся навигацию iframe. В диагностическом прокси с задержкой ответа на 2500 мс зарегистрированы два запроса одной версии: первый прерван через 295 мс, второй завершён через 2511 мс.

Однако устранение серверного iframe само по себе не закрыло дефект: в браузере аудита пустой первоначальный документ оставался и при клиентском создании. Точная внутренняя причина этого поведения браузера не установлена. Контрольный iframe с `srcDoc` отображался сразу. Поэтому итоговое исправление устраняет зависимость от первоначальной HTTP-навигации iframe, а не объявляет проблему решённой по одному успешному SSR-тесту.

## Итоговое исправление

- Iframe вынесен в клиентский `PreviewFrame`, загружаемый через `next/dynamic` с `ssr: false`.
- Редактор сначала получает HTML через существующий защищённый адрес `/preview/<site>/<version>`, с текущими credentials, без кеша. Только после успешного ответа создаётся iframe с `srcDoc`.
- Смена версии и ручное обновление создают новый экземпляр; прежний запрос отменяется. HTML хранится только в памяти компонента.
- Ответы 401/404/500, переход на другую страницу, пустое тело и не-HTML считаются ошибками. Вместо вечной пустоты показывается сообщение на языке интерфейса и остаётся кнопка обновления.
- До готовности показывается локализованный индикатор. В итоговом коде нет таймеров автоматической перезагрузки и циклов повторных запросов.
- Для выбора блоков используется `window.origin`, сохраняющий унаследованный origin документа `srcDoc`. Проверки точного origin и отправителя сообщения сохранены с обеих сторон.
- Обычные якорные клики прокручивают текущий документ без навигации iframe. Base URL указывает на исходную страницу превью: относительные ресурсы и открытие ссылки с модификатором используют правильный адрес. Выбор блока имеет приоритет над якорным действием. Прямая ссылка на отдельное превью сохранена.

Публикация и содержимое клиентских сайтов не менялись. Разрешения iframe не расширялись: и прежнее HTTP-превью, и новое `srcDoc` имеют origin кабинета; собственный код клиента по-прежнему находится в отдельных изолированных рамках.

## Проверки

- `tests/preview-first-open.mts`: серверный вывод для гостя и владельца, настольного и телефонного режима не создаёт iframe; индикатор и прямая ссылка доступны; компонент ждёт получения HTML.
- `tests/preview-html.mts`: credentials, отсутствие кеша, передача AbortSignal, отказ при неуспешном статусе, редиректе, пустом или не-HTML ответе и отмене запроса; отдельная проверка якорей, декодирования ID, возврата наверх, модификаторов и приоритета выбора блока.
- TypeScript, ESLint и локальная production-сборка через webpack прошли. Turbopack в среде агента не может открыть служебный сокет; штатная CI-команда не менялась.
- Изолированный `test:journey` прошёл после изменения способа загрузки: создание, публикация, привязка аккаунта, правки, заявки, проверки, история, резервная копия, повторная публикация и восстановление пароля. Реальные письма и платные AI-вызовы не отправлялись.
- Локальный Chrome: первое открытие сохранённой версии без ручного обновления показало страницу; выбор первого экрана передался редактору, переход Find us остался внутри превью. Локальные снимки не используются для оценки верстки: часть CSS не применяется в браузере аудита.
