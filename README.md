# WINDX QA

Публичная копия исходников WINDX для независимого тестирования.
Срез приложения: `e6396e78fbc91d53ae2fa19883759097c9ecf45b`, подготовлен 9 ноября 2026 года.
Адрес для тестировщика: https://github.com/akela1308/windx-qa

Код приложения, тестов и схем сохранён без изменений. Это отдельная копия:
обновления рабочего WINDX сюда автоматически не переносятся. История рабочего
репозитория, GitHub Actions, настройки локального агента, секреты и рабочие
данные сюда не переносились. В исторической документации заменены личные
контакты и имена домашних каталогов; часть старых снимков экрана исключена.
Сохранены демо-ответы, необходимые для локальной работы без ключа AI,
референсы дизайна и материалы сравнения генератора.

## Начать проверку

1. Скачать код через **Code → Download ZIP** либо выполнить:

   ```sh
   git clone https://github.com/akela1308/windx-qa.git
   cd windx-qa
   ```

2. Открыть [контекст и задания тестеру](docs/tester-handoff-2026-11-07/README.md).
   Редакция документов — 8 ноября, исходная дата имён файлов — 7 ноября.
   В матрице 77 сценариев; все результаты в шаблоне изначально NOT TESTED.
   Исторические ссылки на закрытый рабочий репозиторий могут быть недоступны.

3. Для локального запуска установить Node.js 22 или новее и выполнить:

   ```sh
   npm ci
   ```

   Создать в корне файл `.env.local` с таким содержимым:

   ```dotenv
   AI_DEMO=1
   OPENROUTER_API_KEY=
   WINDX_DATA_DIR=./data-qa
   WINDX_AUTH_ORIGIN=http://127.0.0.1:3216
   WINDX_MAIL_PROVIDER=file
   WINDX_MAIL_TEST=1
   WINDX_SEARCH_HTTP=0
   NEXT_TELEMETRY_DISABLED=1
   ```

   Запустить:

   ```sh
   npm run dev -- --hostname 127.0.0.1 --port 3216
   ```

   Открыть http://127.0.0.1:3216.
   Письма тестового режима сохраняются в `data-qa/auth/test-outbox`.
   Это имитация AI и локальная почта. Она позволяет проверять интерфейс и
   пользовательский путь, но не качество живых Opus/Sonnet, внешнюю доставку
   писем, OAuth, внешний домен или production. Свежая локальная копия начинает
   с пустыми данными; тестовые аккаунты создаются в ней отдельно.

## Проверки кода

```sh
npm run build
npm run typecheck
node --import tsx --test tests/visual-plan.mts tests/ai-model-routing.mts tests/design-references.mts
npm run test:journey
```

Эти команды не заменяют все 77 сценариев и проверку физических телефонов.
Платный эксперимент `experiments/reference-design/run.mts` в обычную проверку
не входит. Внешние интеграции и проверки OPS требуют условий из пакета тестера.

Проверки этой копии 9 ноября: сборка, TypeScript, 10 контрактных тестов и локальный
сквозной пользовательский путь прошли. [Сводка проверки](QA-CHECKS.json). Для сборки
нужен сетевой доступ к Google Fonts. Полный прогон 77 сценариев этим не выполнен.

## Передать результаты

Завести [Issue](https://github.com/akela1308/windx-qa/issues) с ID сценария,
окружением, шагами, ожидаемым и фактическим результатом. Публичные Issues
видны всем: использовать только вымышленные тестовые данные, очищенные логи
и скриншоты. Итоговый отчёт заполнить по шаблону из пакета и передать владельцу
WINDX по согласованному рабочему каналу. Секреты и данные реальных посетителей
в публичные Issues не помещать.

Доступ для чтения не требует приглашения GitHub. Роль участника с правом
push тестировщику не выдавалась. Этот репозиторий не подключён к выкладке
рабочего WINDX.
