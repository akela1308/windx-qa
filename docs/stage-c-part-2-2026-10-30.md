# Этап C, часть 2: форма заявки

30 октября 2026. Продолжение `docs/stage-c-part-1-2026-10-29.md`, по разделу C аудита. Реализован приём заявок в кабинете, без почтового сервиса и без вызовов модели при отправке. Этап D не начат.

Обновление 1 ноября: почтовые уведомления добавлены и проверены отдельно — [отчёт](enquiry-notifications-2026-11-01.md). Ниже сохранено состояние исходного этапа C.

## Что работает

- Две композиции: `contact.form` (имя, email или телефон, сообщение) и `contact.form-inline` (контакт и короткий запрос). Шрифт, цвета, радиус и отступы берутся из оформления сайта. На узком экране поля идут последовательно; размер текста полей не меньше 16px.
- Во вкладке «Заявки» владелец может добавить любую форму без AI и кредитов. Сначала показываются изменения и отдельное превью, затем «Применить» или «Отклонить». Форма вставляется перед подвалом, соседние разделы сохраняются. Добавление попадает в историю, расходы AI равны нулю.
- Обновлены схема, каталог композиций и рабочие промпты. AI может добавить или изменить форму по просьбе клиента, сохраняя остальные способы связи. Получатель не входит в документ сайта и не назначается моделью.
- Email получателя владелец вводит отдельно. До этого публикация формы заблокирована; незаполненный получатель показывается и в панели сведений на подтверждение. Это подтверждение владельцем, без письма с проверочным кодом. Адрес не публикуется в HTML.
- Посетитель видит короткую строку: его данные и сообщение сохраняются в закрытом ящике для ответа владельца сайта. Сообщение об успехе появляется только после записи заявки. Ни запись, ни покупка, ни отправка email этим не подтверждаются.
- При ошибке значения полей остаются. При успехе поля очищаются. Есть обычная HTML-отправка без JavaScript, с отдельным ответом сервера.
- В кабинете показываются последние пять заявок, полный список открывается отдельно, по 50 записей на страницу. Можно открыть email/телефон посетителя или удалить заявку с подтверждением. Удаление всего сайта также удаляет заявки, это явно указано в подтверждении на трёх языках.
- Чужой аккаунт и незарегистрированный гость не могут читать или удалять заявки. Пробный сайт может принимать их после первой публикации; после регистрации тот же сайт и его заявки сохраняются. При копировании сайта заявки и подтверждённый получатель не переносятся.
- Данные заявок не входят в контекст AI-правки и не включаются в публичные превью.

## Хранение и защита

Записи: `data/sites/<id>/enquiries/<sha256>.json` (в Railway под `/data`). Запись создаётся с правами 0600, папка с 0700; временный файл и hard link обеспечивают полностью записанный JSON и отсутствие перезаписи при одновременной одинаковой отправке. Отдельный секрет подписи лежит в `data/auth/enquiry-key`, 0600, в git не попадает.

Токен формы подписан, ограничен 24 часами и привязан к сайту, опубликованной версии, моменту публикации и разделу. Снятие с публикации и повторная публикация отзывают старую форму немедленно на сервере. При попытке отправить её посетителю предлагается обновить страницу. Публичная страница по-прежнему кешируется на пять секунд, ответ об отсутствии сайта не кешируется.

Проверяется исходный домен отправки. Proxy перезаписывает служебный заголовок фактическим Host, клиентское значение не принимается. В Next.js отключена нормализация URL Proxy, а rewrite строится через обычный URL: иначе локальный `127.0.0.1` превращался в `localhost`, запускал повторный HTTP-запрос и терял исходный Host. Это проверено через настоящий поддомен, а не только прямой `/live/...`.

Есть скрытое поле от ботов, проверка обязательных полей и контакта, ограничения длины, лимит тела запроса 64 КиБ. Повтор одного и того же запроса не создаёт вторую запись. Простые ограничения частоты: пять попыток за десять минут на сайт и IP-ключ, общий предел 60 за час на сайт. Сырой IP не сохраняется; для кратковременного ключа используется HMAC. При отсутствии `X-Real-IP` действует общий ключ `unknown`, поэтому лимит становится общим для таких посетителей. IP не определяет владельца и не даёт доступ к сайту.

Счётчики частоты находятся в памяти одного процесса и сбрасываются при перезапуске. Для нынешнего одного экземпляра приложения это простая стартовая защита, а не защита от распределённой атаки. При нескольких экземплярах потребуется общее хранилище счётчиков. В ящике предусмотрен предел около 1000 записей (при одновременных запросах возможен небольшой выход за предел); заполненный ящик возвращает ошибку, посетитель не получает ложного успеха. Автоматического удаления по сроку пока нет, удаляет владелец. Резервные копии и политика хранения требуют отдельного решения перед масштабированием.

## Как подключать письмо позднее

Сейчас нет провайдера, ключей, отправки или фоновой очереди. В интерфейсе прямо написано, что письма не отправляются.

После отдельного разрешения на сервис: сначала надёжно сохранить заявку, затем добавить задачу уведомления с уникальным ID заявки в очередь. Получатель должен быть подтверждён владельцем и проверен через email. Отправитель использует настроенный домен с SPF/DKIM/DMARC. Повторы очереди не должны создавать одинаковые письма; ошибка отправки не удаляет заявку и не превращает успешную запись в потерю сообщения. В кабинете нужны отдельные статусы записи и уведомления. Содержание письма по умолчанию минимальное, со ссылкой на закрытую заявку, без пересылки лишних персональных данных. Подключение, расходы, сроки хранения и повторов согласуются отдельно.

Текущая короткая строка у формы не заменяет сведения владельца о работе с данными и privacy notice. Этот этап не заявляет юридического соответствия; проверка относящихся к бизнесу требований остаётся отдельным этапом.

## Проверено

Все проверки используют временные локальные данные и `AI_DEMO=1`, без платных модельных запросов и отправки писем.

```sh
npm run build
node --import tsx tests/enquiries.mts
node --import tsx tests/enquiries-http.mts
node --import tsx tests/auth-http.mts
node --import tsx tests/guest-trial.mts
node --import tsx tests/auth-isolation.mts
node --import tsx tests/google-auth.mts
node --import tsx tests/edit-decoration.mts
node --import tsx tests/ai-json-request.mts
npx eslint src experiments/exp1/a next.config.ts tests/enquiries.mts tests/enquiries-http.mts
```

HTTP-тесты поднимают локальную production-сборку на портах 3198 и 3197, затем останавливают свои серверы и удаляют только свои временные данные. Проверены обе формы, поддомен, подпись, срок токена, поддельный исходный домен, honeypot, размер запроса, повторная отправка, HTML без JavaScript, ошибки диска, лимит частоты, закрытый ящик, прямые действия чужого аккаунта, добавление/применение, блокировка публикации без получателя, копия сайта, удаление, offline и повторная публикация. Старые проверки входа, гостевой регистрации и AI-правок также пройдены.

Общий `npm run lint` по всему репозиторию остаётся красным из-за прежних двух `no-explicit-any` в `experiments/exp1/smoke.mts`; есть прежний unused import в `experiments/exp1b/build-prompts.ts`. Общий `npm run typecheck` для старых скриптов тоже остаётся красным: абсолютные пути от другого Mac в smoke.mts, синхронное использование прежнего getStore в старых тестах и настройки импорта .ts в free-editor.mts. Production-сборка и её проверка типов проходят; новые тесты выполняются успешно. Изменённый код проходит отдельный eslint. Ошибки вне задачи не исправлялись.

В браузере выполнен полный путь на одноразовом локальном сайте: добавить полную форму, подтвердить получателя, просмотреть/применить, опубликовать, отправить, прочитать в закрытой вкладке. Затем добавлена компактная форма и отправлен второй запрос при ширине 390px. Поля помещаются в 350px с отступами по 20px. Это проверка мобильного размера на компьютере, настоящий телефон пока не проверен.

## Как проверить вручную

1. Войти, открыть свой сайт и вкладку «Заявки».
2. Ввести email получателя и подтвердить. Письмо не придёт, это ожидаемо.
3. Добавить обычную или короткую форму, открыть превью предложения, применить.
4. Подтвердить остальные сведения сайта и опубликовать изменения.
5. Открыть публичный адрес, заполнить форму тестовыми сведениями и отправить.
6. Вернуться в кабинет и обновить вкладку «Заявки». Сообщение должно быть в списке.
7. Оставить старую публичную вкладку открытой, снять сайт с публикации. Отправка старой формы должна дать ошибку, новая загрузка страницы должна дать 404 без кеша.
8. Опубликовать снова. Старый токен по-прежнему не принимается, после обновления страницы новая форма работает.
