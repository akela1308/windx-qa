## Контакты

Во всех трёх композициях `contact.big-type`, `contact.split`, `contact.band` телефон и почта имеют собственные ссылки. Основная кнопка может вести в другое место: она больше не определяет, какой способ связи останется доступным. В `split` и `band` добавлено отдельное поле email. Схема в системном промпте пересобрана.

Старые документы тоже поддержаны: если отдельное поле контакта отсутствует, а кнопка содержит `tel:` или `mailto:`, контакт берётся из неё. Отсутствующие сведения не выдумываются. Пунктуация и пробелы в телефонном номере не попадают в номер для набора.

## Кеширование публикации

Ответ 404 содержит `Cache-Control: no-store, max-age=0`.

Опубликованная страница содержит `Cache-Control: public, max-age=5, s-maxage=0, must-revalidate`. Браузер может использовать сохранённую страницу до 5 секунд, после этого должен перепроверить её. Общий кеш должен перепроверять каждый запрос. Уже открытая вкладка сама по себе не исчезает после снятия публикации.

Проверка проведена через реальный HTTP на локальной production-сборке, поскольку dev-режим Next.js подменяет Cache-Control. В Chrome с шириной 390 пикселей проверен тот же URL без обходного параметра: опубликованный сайт, затем 404 после Take offline, затем страница после повторной публикации. HTTP-заголовки и скриншоты сохранены в [папке проверки](stage-c-part-1-2026-10-29/).

На публичном сервере новый код ещё не развёрнут. Повторная проверка именно с настоящего телефона после развёртывания остаётся открытой. Старый тестовый сайт `4f9e5ea7` на `windx-publication-test-20261029.windx.app` снят с публикации через рабочий кабинет, публичный адрес показал 404.

## Границы AI правки

Промпт теперь явно отделяет узкую просьбу от переработки дизайна. Он запрещает менять соседние разделы, их порядок, композиции и общие стили ради выполнения общих предпочтений дизайна. Дополнительные идеи предлагаются текстом без операций изменения.

В коде устранена отдельная причина расширения правки: глобальная проверка требовала добавить рисунок, смелые элементы и переставить FAQ даже на старом сайте. Для правок эти композиционные требования больше не запускаются. Проверки схемы, контраста и обязательных ограничений сохранены, новые запрещённые обороты проверяются; унаследованные замечания к текстам не заставляют переписывать несвязанные блоки. При создании нового сайта глобальные проверки сохранены.

Перед применением каждая AI-правка теперь показывает фактический список затронутых областей и изменённые значения «Было / Будет», а также ссылку на предлагаемый вариант страницы. Этот список вычисляется по документам, независимо от объяснения модели. Изменения композиции, оформления, порядка, метаданных и списка фактов тоже видны. Клиент может применить или отклонить предложение. До применения текущая версия и опубликованный сайт остаются прежними. Применение не публикует новую версию автоматически.

Предложение сохраняется при обновлении страницы и переключении вкладок редактора. Устаревшее предложение нельзя применить к другой версии сайта. Расход AI-запроса сохраняется в отдельной записи даже при отклонении предложения. Тексты обзора добавлены на английском, русском и испанском.

## Заголовок и описание страницы

Слой правок уже поддерживал операцию `meta`, а HTML уже использовал `meta.title` и `meta.description`. Поэтому добавлено правило в промпт: при изменении названия бизнеса, основного предложения, места или темы страницы обновлять ставшие неверными title и description в том же предложении. Для косметических правок и смены контактов точные метаданные сохраняются. В обзоре клиент видит и эти изменения. Рендер обоих полей проверен тестом. Прогон обновлённого промпта через платную модель не выполнялся; проверки использовали готовые данные и демо-режим.

Общий `npm run typecheck` по всем экспериментам по-прежнему блокируют старые абсолютные пути к другому компьютеру в `experiments/exp1/smoke.mts` и связанные с ними ошибки типов. Эти экспериментальные файлы не менялись.

Для ручной проверки интерфейса без платной модели:

```bash
AI_DEMO=1 npm run dev
```

Создать сайт, попросить `Make the hero calmer`, проверить обзор и текущий номер версии, затем выбрать Apply или Discard. Для проверки кеша использовать production-сборку (`npm run build`, затем `AI_DEMO=1 npm run start`), пройти Publish, Take offline и повторный Publish на одном URL. После снятия публикации подождать больше 5 секунд и обновить ранее открытую вкладку.
