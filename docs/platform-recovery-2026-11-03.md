# Резерв всей платформы и проверка восстановления

3 ноября 2026 года. Следующий шаг после исправления первого открытия превью.

## Что реализовано

Это операторский резерв всей платформы, отдельный от пользовательского файла `.windx.json`.

В архив входят канонические каталоги `auth`, `sites`, `domains`: аккаунты и хеши паролей, принадлежность сайтов, все версии, публикации, собственные изображения, заявки, настройки получателей, история проверок, предложения и реестр доменов. Настройки приложения и ключи внешних интеграций включаются только внутрь зашифрованного содержимого. Git-код хранится отдельно; свежие автоматические копии указывают commit, из которого собран сервер.

Не копируются старые архивы, служебный `lost+found`, промежуточные файлы и файловые блокировки. Неизвестный каталог данных вызывает ошибку: новая функция не должна незаметно остаться без резерва.

Используются RSA-OAEP-SHA256 и AES-256-GCM с новым случайным ключом каждого архива, gzip и контрольными суммами файлов. Открытый ключ находится в `ops/backup-public-key.pem`. **Закрытый ключ хранится только на этом Mac:** `data/platform-recovery/private.pem`, права 600. Его нет в git, Railway и GitHub Actions.

Снимок создаётся без остановки сайта. Инструмент сравнивает состав каталогов, inode, ctime, mtime и размеры до и после чтения; проверяет JSON и наличие сохранённых и опубликованных версий. При изменении данных попытка отклоняется, а не выдаётся за согласованный резерв. Фоновая задача допускает три попытки, затем повторяется через час. Активная запись может отложить снимок; это не транзакционный snapshot базы данных.

## Ежедневный процесс

Фоновый обработчик включается только при совпадении project/environment/service WINDX production и `/data`. Он создаёт одну копию на дату UTC, проверяет уже созданный файл и хранит три последних зашифрованных архива. Задача резервирования не блокирует запуск сайта; сбой виден в серверном журнале.

Отдельный GitHub Actions workflow ежедневно в **04:17 UTC** скачивает готовую копию по HTTPS с существующим project token, проверяет возраст до 30 часов, ключ, размер и SHA-256 и хранит зашифрованный artifact 14 дней. Для выгрузки действует предел 20 МиБ; при превышении задача завершается ошибкой, а не повышает тариф. Репозиторий должен оставаться приватным, запуск разрешён только из main. Закрытый ключ для выгрузки не нужен. Уведомления о неуспехе зависят от настроек GitHub владельца; отдельная внешняя система оповещения здесь не подключалась.

Служебный GET `/internal/platform-backup` отдаёт только зашифрованный файл или сводку без настроек. Активный project token проверяется через [официальный запрос Railway](https://docs.railway.com/integrations/api#using-a-project-token): должны совпасть project и environment WINDX. Нельзя передать токен в URL, выбрать произвольный путь или запросить незашифрованный файл. Есть no-store, ограничение запросов и размера; сбой API проверки закрывает доступ. Railway CLI для файлов требует SSH-ключ, поэтому этот более широкий ключ не передавался в CI.

Новый платный сервис и новые credentials не создавались. Используются существующие Railway и GitHub Actions. Нативные Railway volume backups не включались: [по документации они тарифицируются как дополнительное хранение](https://docs.railway.com/volumes/backups). Использование существующих ресурсов остаётся в пределах их условий; бесплатность при любом будущем объёме не обещается.

## Реальное восстановление проверено

Через ранее разрешённый SSH-ключ снята копия настоящего `/data` cabinet, скачана на Mac вне Railway и восстановлена в новый отдельный каталог. Рабочее хранилище не перезаписывалось.

| Содержимое | Количество |
| --- | ---: |
| Аккаунты | 3 |
| Сайты | 15 |
| Сохранённые версии | 26 |
| Собственные изображения | 3 |
| Заявки | 1 |
| Файлы исходного снимка | 118 |
| Размер зашифрованного архива | 96 056 байт |

Production-сборка запущена на восстановленных данных в localhost с отключёнными внешними AI, почтой и управлением доменами. Проверены четыре сайта зарегистрированных владельцев, обе опубликованные страницы и все три изображения. Чужой аккаунт и анонимный посетитель не получили приватное превью. Остальные записи сайтов сохранены со своими прежними идентификаторами и принадлежностью; тестовые гостевые/непринятые сайты не присваивались новым пользователям.

Сессии для проверки реальных записей создавались операторским тестом только в изолированной копии и удалены после него. Пароли действующих владельцев не запрашивались и не менялись. Отдельный синтетический сценарий подтвердил аутентификацию прежним паролем после восстановления и недействительность старого session token.

## Безопасное восстановление

Восстановление разрешено только в новый каталог. Ни один существующий каталог не перезаписывается. Данные публикуются в `data/` этого нового каталога только после проверки GCM, контрольных сумм, полного завершающего манифеста и ссылок на версии. Повреждённый или неполный архив удаляет только собственный незавершённый результат.

Аккаунты, пароли и принадлежность сохраняются. Старые сессии, одноразовые ссылки, приглашения и AI-подтверждения не возвращаются в действие. Ожидающие уведомления переводятся в отменённые: восстановление не должно повторно отправить старые письма. Заявки остаются доступны владельцу. Для ещё не принятого приглашения потребуется новое; анонимная проба не становится аккаунтом автоматически.

`configuration.json` сохраняется отдельно с правами 600 и **не применяется автоматически**. Сетевые домены, DNS, сертификаты и доступность внешних ключей проверяются оператором перед возвратом живого трафика. Настройка хостинга и регистратора не восстанавливается одним JSON-файлом.

## Проверки кода

- `tests/platform-backups.mts`: полный цикл шифрования и восстановления, бинарные файлы, заявки, предложения, настройки, снятие старых сессий/ссылок/подтверждений, запрет повторной отправки писем; повреждение, неверный ключ, выход за каталог, абсолютный путь, дубли, неполный архив, отсутствующая версия, симлинк, перезапись; повторный запуск за день и устаревшая блокировка.
- `tests/platform-backup-export.mts`: scope project/environment, отсутствие токена, отказ при сбое провайдера, закрытые метаданные, пути, симлинки, старый снимок, ограничитель запросов и сохранность существующей папки скачивания.
- `tests/platform-recovery-http.mts`: настоящий HTTP-сервер на восстановленной копии, аутентификация синтетического аккаунта, права владельца, публичные страницы и изображения. При отдельном явном параметре — проверка восстановленного production-снимка только локально.
- TypeScript, ESLint, production-сборка и существующий `test:journey` прошли.

Доказательства без значений секретов: `data/verification/platform-recovery-2026-11-03/`. Зашифрованные копии и закрытый ключ — в игнорируемой папке `data/platform-recovery/`.

## Выкладка и независимая выгрузка

Код резервирования и закрытого HTTPS-канала: `e6327fa`. [Штатная выкладка 41648388484](https://github.com/akela1308/windx/actions/runs/41648388484) завершилась **SUCCESS**. Серверный обработчик сам создал снимок без ручного вызова; данные исходного снимка относятся к `6ae8dd8`, что правильно отражено в его release.

[Первый успешный offsite-запуск 41648985496](https://github.com/akela1308/windx/actions/runs/41648985496) завершился **SUCCESS** и сохранил зашифрованный artifact в приватном репозитории. Он запущен вручную для проверки того же задания, которое настроено на ежедневное расписание. Следующий плановый запуск после этой сессии ещё не наблюдался.

`npm run backup:pull` действительно скачал эту копию из GitHub. Она заново расшифрована и проверена настоящим HTTP-сервером: 3 аккаунта, 15 сайтов, 26 версий, 1 заявка, 3 изображения; четыре сайта зарегистрированных владельцев доступны своим владельцам, две опубликованные страницы отрисованы. Старые сессии не возобновлялись. Закрытый ключ не передавался ни в Railway, ни в GitHub.

На рабочем HTTPS-канале подтверждены 401 без токена, 403 с неверным токеном и 200 с действующим project token. Ответ зашифрованного файла совпал по SHA-256; Cache-Control — private/no-store. Вход WINDX и существующая опубликованная демонстрация после выкладки ответили 200.

После проверки расшифрованные рабочие копии с настройками удалены; сохранены зашифрованные архивы, ключ и отчёты без секретов. Это не удаление исходных данных: рабочий volume не перезаписывался, архивы повторно восстанавливаются тем же инструментом.

## Что требуется владельцу

**Сохранить закрытый ключ ещё в одном безопасном месте**, например в защищённом менеджере паролей или на втором личном устройстве. Потеря этого Mac вместе с единственным экземпляром ключа сделает зашифрованные архивы непригодными. Новую копию ключа во внешнее место без отдельного указания владельца не отправляли. Ротация ключа не делает прежние архивы расшифровываемыми новым ключом.

Команды и порядок аварийного запуска: [операторская инструкция](platform-recovery-runbook.md).
