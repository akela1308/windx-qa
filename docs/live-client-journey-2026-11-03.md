# Живой проход нового клиента WINDX

3 ноября 2026 года. Проверка рабочего `https://www.windx.app` через интерфейс, настоящую модель и настоящий Gmail. Технический демо-сайт, без реальных заказов и персональных данных посетителя.

## Результат

Основная цепочка пройдена: регистрация владельцем → письмо → подтверждение почты → создание сайта → просмотр AI-правки → сохранение ручного текста → публикация → отправка заявки посетителем → закрытый ящик → настоящее уведомление владельцу → переход из письма к заявке.

Это доказательство одного живого сценария, а не заявление о полной готовности всех функций. Загрузка файла и мобильная ширина в этом проходе не подтверждены: ограничения инструментов описаны ниже.

## Найдено и исправлено: сообщение об истёкшей ссылке

Регистрация была во встроенном браузере, а письмо открыто в Chrome с другим аккаунтом WINDX. Проверка принадлежности ссылки работала, но объяснение было неверным: пользователю говорили об истечении срока. Исходное письмо было свежим; та же ссылка успешно подтвердила почту в браузере с нужным аккаунтом. Статус на сервере вручную не менялся, токен из серверного хранилища не извлекался.

Исправление `dce31a6` добавляет отдельное состояние другого аккаунта, объяснение и кнопку выхода для смены аккаунта. Чужой аккаунт не расходует ссылку и не узнаёт адрес её получателя. Неверные, использованные и просроченные ссылки остаются недействительными. Переводы EN/RU/ES. Убрано лишнее серверное обновление после подтверждения, возвращавшее fragment в адресную строку.

Выкладка: GitHub Actions `41677165378`, **SUCCESS**, коммит `dce31a689e111592b181871c0f1be7ee6395ff3c`. На рабочем сайте повторно открыт аккаунт с заголовком «Почта подтверждена».

Проверки исправления:

```sh
node --import tsx tests/account-security.mts
npx next build --webpack
node --import tsx tests/verification-account-http.mts
```

Все три команды прошли. HTTP-проверка на изолированной production-сборке проверяет другой аккаунт, отсутствие расходования ссылки, смену только текущей сессии, успешное подтверждение владельцем и запрет повторного использования. Новое сообщение другого аккаунта проверено серверным тестом; повторный свежий production-токен для этой ветки не создавался после успешного подтверждения адреса.

## Что осталось

1. **Свои изображения:** файл подготовлен, но два штатных вызова выбора файла во встроенном браузере завершились таймаутом; управление нативным окном Codex недоступно инструменту. Файл не загружен. Это ограничение данной автоматизированной проверки, не доказанный дефект загрузки WINDX. Нужен повтор через работоспособный выбор файла в Chrome либо ручная загрузка.
2. **Мобильная ширина:** запрошенные overrides 390 px в IAB и Chrome фактически не применились (DOM продолжал показывать ширину 1280/1470 px). Настройки возвращены обратно. Проверка телефона или ширины 390 px этим проходом не подтверждена.
3. **Длинное тире:** общий запрет в промпте и валидаторе отклонил дословно заданный тестовый заголовок; AI заменил тире двоеточием и объяснил это. Ручная форма с тире дала общий отказ без точной причины. Продуктовое ограничение не менялось. Следует отдельно решить приоритет дословной просьбы пользователя и выдавать конкретную ошибку в ручном редакторе.
4. **Ожидание AI:** при фактическом выполнении правки карточка оценки продолжает говорить «Запрос ещё не отправлен». Кнопки при реальном выполнении блокируются; текст ожидания стоит уточнить. Первый семантический клик инструмента не запустил запрос; проверка статуса показала неиспользованную оценку, после обычного нажатия выполнено ровно одно действие. Не выдавать сбой управления инструментом за дополнительный AI-вызов.
5. **Три проверки:** в этом проходе не запускались заново. Диалог публикации честно показал «Не запускалась»; индексация, юридическое соответствие и полноценная мобильная работоспособность не заявляются проверенными этим сценарием.
6. **Google и внешний домен:** в этот проход не входили; прежние незавершённые настройки этим отчётом не закрываются.
