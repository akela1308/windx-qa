# Замечания владельца: исправления 1 ноября

Источник: переданный владельцем файл `WINDX_замечания_для_разработчика_2026_10_31.md`. В этой части закрываются ручной текст/изображения и связанные с ними дефекты географии, языка и переходов из проверок. Приложенный документ использован как материал для анализа; предложения о тарифах, операторе и юридических текстах не превращены в утверждённые данные или цены.

## Сделано

### Страна и границы требований

Вступление больше не утверждает, что любой сайт принадлежит британскому бизнесу. До запуска интерфейс просит подтвердить страну бизнеса и применимость рынка UK, отдельно сохраняются страны клиентов. При явном названии одной из поддержанных распознавателем стран в исходном описании показывается предположение с цитатой. Оно не сохраняется как ответ автоматически. `Lagos` без страны не даёт предположения: город, язык и телефон не используются как доказательство юрисдикции.

При неизвестной стране британские правовые правила не запускаются даже при старом ответе `market: uk`. При подтверждённом другом рынке показывается отсутствие местной правовой проверки; остаются фактическая карта данных и общие наблюдения о функциях. Если владелец подтвердил работу с рынком UK, показывается точная граница британских источников, без утверждения об охвате других стран. Изменение страны сбрасывает старый ответ о рынке в «неизвестно», требует нового подтверждения и делает прежний отчёт устаревшим.

Поддержка юридических правил новых стран не добавлялась. Дата обзора официальных источников остаётся 30 октября, новый номер правил отмечает изменение области применимости, а не новый правовой обзор. Распознаватель названий стран ограничен; для остальных стран работает ручной ввод, без ложного предположения.

### Единый язык

Новые `rationale` и `reply` получают явную инструкцию использовать язык интерфейса, с возможностью явно попросить иной язык ответа. Удалены конфликтовавшие инструкции брать язык просто из запроса. Язык текста сайта этим не меняется. Демо-ответы и системные ошибки создания/правки следуют UI, а не наличию кириллицы в запросе.

Форма получателя заявок использует собственную ошибку EN/RU/ES и не запускает нативную подсказку браузера. Адрес по-прежнему проверяется сервером. Смена языка сама по себе не должна сбрасывать контролируемый ввод. Исторические сохранённые ответы не переводились заново. Проверен демо-провайдер и построение промпта; гарантировать каждую будущую реплику внешней модели по этому тесту нельзя, реальный платный запрос в этой части не запускался.

### Проверки и следующий шаг

- `Site checks` / «Проверки сайта»: заметная рамка, тень, фокус клавиатуры, стрелка и раскрытое состояние. Декоративные серые точки убраны.
- `Visitor experience` / «Удобство сайта»: сохраняются явные ограничения. Реальная отправка заявки, почта, внешние ссылки и пользовательский JavaScript не объявлены проверенными.
- Контакты, фотографии и alt из проверки удобства ведут в ручной редактор. Заголовок/описание из поиска открывают метаданные. Для AI-просьбы добавляется версия исходного отчёта, сам вызов AI не запускается автоматически.
- Для требующих специалиста замечаний есть раскрываемый следующий шаг и источник/ограничения. Внешняя авторизация не запускается.
- `Connect Search Console` открывает честное объяснение: встроенного подключения пока нет, данные Google WINDX не получает. Есть ссылка на самостоятельную настройку в Google. Никакого фиктивного подключения или статистики.
- Отчёты, выбранная история и ответы сохраняются при переключении вкладок к правке и обратно. После применения правки старый отчёт отмечается устаревшим. Проверка поиска по отличающейся опубликованной версии сначала отправляет к проверке текущего черновика, чтобы не редактировать неправильный блок по старому индексу.

Это ещё не полноценная система задач: нет отдельного постоянного статуса решения каждой задачи, автоматической повторной проверки после применения и регулярного сопровождения. Повторная проверка запускается кнопкой владельца.

### Исправление придуманных сведений

В списке фактов доступен переход к соответствующему разделу ручного редактора. Во время реальной правки владелец может явно отметить конкретное неподтверждённое сведение, которое заменил или удалил. Удаление этого старого пункта видно в предложении изменений и применяется вместе с новой версией. Без изменения содержания убрать пункт этим действием нельзя; сведения других разделов и остальные неподтверждённые факты не подтверждаются автоматически. Неоднозначные составные утверждения требуют решения владельца, семантическая «истинность» текста не объявляется автоматически доказанной.
